# 實驗 1：封包序號與逐包紀錄

兩支程式，搭配現有的 CC1352 v8 TX／RX 韌體使用，不需要改韌體。只需要 Python 3 和 pyserial（你們原本就有裝）。

| 程式 | 在哪台電腦跑 | 做什麼 |
| --- | --- | --- |
| `seq_tx.py` | 接 TX 板的筆電 | 依計畫送出帶序號的 230 bytes 封包 |
| `seq_rx_logger.py` | 接 RX 板的筆電 | 逐包紀錄、即時顯示、結束時輸出統計 |

## 使用順序

1. 兩台筆電先對時（Windows：設定 → 時間與語言 → 立即同步）。
2. **先啟動 RX**：`python seq_rx_logger.py --label 2km_LNA`
3. **再啟動 TX**：`python seq_tx.py --plan 10x120,100x120 --repeat 3 --label 2km_LNA`
4. TX 送完後，RX 在 15 秒沒收到新封包時會自動結束並印出總結，也可以按 Ctrl+C 提早結束。

COM port 預設自動偵測。如果一台電腦同時接兩塊板子，或偵測錯了，用 `--list` 看清單，再用 `--port COM5` 指定。

## 建議的三種跑法

| 用途 | TX 指令 | 說明 |
| --- | --- | --- |
| 桌面健康檢查 | `--plan 10x60,100x60` | 兩塊板子放同一張桌上，不接 PA／LNA。總結的「健康檢查判定」要顯示「通過」才出門 |
| 找出最高速率 | `--plan 50x20,100x20,150x20,200x20` | 桌面上跑。成功率開始掉的那個速率，代表韌體或 RF 送不完，場測要用比它低的速率 |
| 場測 | `--plan 10x120,100x120 --repeat 3` | 低負載 2 分鐘、影像負載 2 分鐘，交替 3 次。100 包/秒約等於 v3.1.0 傳影像時的資料量 |

`--plan` 的格式是「速率x秒數」，多段用逗號分隔，每一段稱為一個「段落」，依序編號 0、1、2…

## 輸出

RX 每次執行會建立一個資料夾 `results/<label>_<日期時間>/`：

| 檔案 | 內容 |
| --- | --- |
| `summary.txt` | 人看的總結：每個段落的成功率、RSSI、掉包次數、最長連續掉包、資料品質檢查 |
| `summary.json` | 同上，給程式讀 |
| `packets.csv` | 每收到一包一列：`rx_time` 收到時間、`seq` 全域序號、`seg_id` 段落、`seg_index` 段落內編號、`seg_total` 該段應送包數、`rate_pps` 速率、`rssi_dbm`、`status_hex` 韌體狀態位元組、`fw_len` 韌體回報長度、`crc_ok`、`kind`（`ok`／`duplicate`／`crc_error`／`misaligned`／`short`／`foreign`）、`latency_ms` 粗估延遲 |
| `per_second.csv` | 每個段落每一秒（以 TX 送出順序切）的應收、實收、成功率、RSSI 平均／最小／最大 |
| `bursts.csv` | 連續掉包長度的分布：掉 1 包的有幾次、連續掉 2 包的有幾次… |
| `raw.bin` | 序列埠收到的原始資料。分析有問題時可以重算：`python seq_rx_logger.py --replay results/.../raw.bin` |

TX 會在 `results/tx_<label>_<日期時間>.csv` 留下每段的計畫包數、實際送出包數、實際速率。RX 有「一包都沒收到」的段落時，用這個檔對照。

## 怎麼看結果

- **成功率**＝實收 ÷ 應收。應收數量寫在每個封包裡，所以就算某段最後幾包都掉了也算得準。
- **最長連續掉包、平均每次掉幾包**：數字越大代表掉包越成串，對影像的影響和零星掉包不同。
- **延遲**只是粗估，兩台電腦沒對時就沒有意義。
- **資料品質**出現「未對齊」、「CRC 錯誤」或「過短」時，數據不能用。通常是 TX 送太快、韌體緩衝區滿了，請重開 TX 板和 `seq_tx.py`，並降低速率。

## 封包格式（230 bytes）

| 欄位 | 長度 | 內容 |
| --- | --- | --- |
| magic | 4 B | `A7 53 45 51`，確認封包有對齊 |
| seq | 4 B | 全域序號 |
| seg_id | 2 B | 段落編號 |
| rate | 2 B | 該段速率（包/秒） |
| seg_index | 4 B | 段落內編號 |
| seg_total | 4 B | 該段應送包數 |
| tx_time | 8 B | TX 送出時間 |
| padding | 198 B | 固定內容 |
| crc32 | 4 B | 前 226 bytes 的 CRC32 |
